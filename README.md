# 骑马订核版台（左侧装订 · 每张纸 4 页）

短册送入骑马订线前，用于核对每张纸正反面页序的浏览器核版台。解决的实际问题：
拼版员把短册送入骑马订线前，容易看反纸张背面的左右页序，而错误往往要等
折叠后才暴露。本工具按公式直接计算页码（无预制数据表、无占位分支），逐张
预览正面/背面，供上线前核对。

- 装订方式：**左侧装订（左订口）骑马订套帖**
- 每张纸沿竖直中线对折，承载 **4 个印刷页**（正面 2 页 + 背面 2 页）
- 前端：React + TypeScript + Vite
- 单测：Vitest（纯映射函数）；端到端：Playwright（构建产物验收）

## 页码公式与实体纸张顺序

输入总页数 `N`，合法范围：**4 ≤ N ≤ 64 的整数，且 N 能被 4 整除**；
纸张总数为 `N / 4`。

纸张按 `i = 0, 1, 2, …, N/4−1` **由外层到内层**排列：

| i | 正面 左页 | 正面 右页 | 背面 左页 | 背面 右页 |
|---|-----------|-----------|-----------|-----------|
| i | `N − 2i`  | `1 + 2i`  | `2 + 2i`  | `N − 1 − 2i` |

代码见 `src/lib/imposition.ts` 的 `sheetAt()`。

### 为什么是这个顺序（实体纸张）

骑马订是**套帖**：所有纸张沿同一竖直中线对折后，从外到内一张套一张，
最后在书脊折缝处上两个骑马钉。因此列表里的纸张顺序就是实物叠放顺序：

- **第 1 张（i=0，最外层）**：摊开后朝读者的“正面”上，右页是封面
  **第 1 页**，左页是封底/全书最后一页 **第 N 页**——摊开的整张纸
  本身就是一个从 N 到 1 的大跨页。
- **“背面”指沿纸张竖直中线翻转（绕竖直轴翻面）后看到的阅读方向**，
  不是把纸上下翻转。翻过来后，原来在正面右侧的那一半纸转到了观察者的
  左侧，所以**背面左页紧跟封面，是第 2 页；背面右页是第 N−1 页**。
  这正是最容易看反的一对：背面不是“N−1 在左、2 在右”。
- **越往内（i 增大）**：正面左页 `N, N−2, N−4, …` 递减、正面右页
  `1, 3, 5, …` 递增；背面左页 `2, 4, 6, …` 递增、背面右页
  `N−1, N−3, …` 递减。
- **最内层（i=N/4−1）**：四个页码连续，例如 N=16 最内张为
  正面 左 10 / 右 7，背面 左 8 / 右 9；折好书帖后按阅读方向即 7→8→9→10。

以 N=8 为例（共 2 张纸，外层包住内层）：

| 纸张 | 正面（左 / 右） | 背面（左 / 右，竖直翻转后） |
|------|-----------------|------------------------------|
| 第 1 张（最外） | 8 / 1 | 2 / 7 |
| 第 2 张（最内） | 6 / 3 | 4 / 5 |

## 输入处理规则

输入框每次变更都经过纯函数 `parseTotalPages(raw)`（`src/lib/imposition.ts`）：

- **空输入 / 纯空白**：立即清除旧拼版，显示空态提示。
- **小数或非数字文本**（含 `8.5`、`12页`、`1e2`、`12.0`）：立即清除旧拼版，
  提示“必须是整数”。
- **越界**（小于 4 或大于 64）：立即清除旧拼版，提示范围。
- **范围内但不能被 4 整除**（如 6、10、62）：立即清除旧拼版，提示整除要求。
- **合法**：显示纸张总数，并按外层到内层列出全部纸张。

非法状态不携带任何纸张数据，UI 也不会保留上一次的结果。

## 走纸方向演练区

核版台下方是独立的**走纸方向演练区**，解决的现场问题：换纸或背印重上机时，
操作员容易把“顺时针转台”和“沿机器进纸轴翻纸”的先后效果当成可交换，
而页码核版无法说明标记纸的空间朝向。

- **起点**：正面朝上、进纸箭头朝北（机器进纸方向）、四色角标 A–D 归位
  （A 西北、B 东北、C 东南、D 西南）。
- **动作**：仅「顺时针旋转 90°」与「沿进纸轴翻纸」两个现场动作；
  界面实时绘出当前面、箭头指向、角标落位与动作轨迹。
- **领域模型**（`src/lib/paperDrill.ts`）：纸张姿态归一为**八种**
  （二面体群 D4：4 个旋转量 × 正/背面），每步按不可交换的空间变换
  增量合成，同时把动作序列从起点**确定性重放**；增量姿态与重放结果
  不一致时拒绝本次动作，并把轨迹矫正为可信轨迹（动作序列不变、
  姿态以重放为准），画面停在最后可信状态，同时提示「演练轨迹无效」。
- **群性质**：连续四次旋转或两次翻纸回到起点；旋转后翻纸与翻纸后旋转
  落到不同姿态（角标布局不同），即两动作不可交换。
- **上限**：轨迹达到 **24 步**后不再接收动作，提示刷新页面可重新演练。
- **隔离**：演练复用核版的正/背面语义与纸张视觉规范，但不读取、不改写
  拼版结果；操作演练不会重算、清除或改变已有总页数及各纸展示面，
  核版输入变化也不影响演练轨迹。

## 钉位检测区

走纸演练区下方是独立的**钉位检测区**，解决的现场问题：成册下线后，质检员
拿到的是沿书脊自上而下的一串实际钉痕，里面可能夹着误识别（多余钉痕）或
漏钉；页码核版与走纸演练都无法判断钉位是否合格。本区按顺序填写四项：

- **书脊长度**（毫米，顶端为 0）、**允许偏差**（单侧容差，毫米）；
- **计划钉位**与**实测钉痕**：自上而下的毫米坐标，用空格、半角/全角逗号、
  顿号或分号分隔（如 `30, 100, 170, 240`）。

四个字段均接受**任意大小的精确十进制数**：解析、校验、动态规划与结果展示
全程按十进制原文用定点 `BigInt` 计算，不经过 IEEE-754 双精度。因此超过
`Number.MAX_SAFE_INTEGER`（2^53−1）的书脊长度会逐位保留，两个数学上严格
递增的大整数不会因舍入相同被误判重复，超大容差下 DP 总代价也不会溢出成
`Infinity` 而选错路径。

点击「分析钉位」后展示：**配对连线图**（左列计划位、右列实测痕，连线
绿色合格、红色超差；漏钉/多痕用不同色点标出）、每对的**毫米偏差**（带符号，
正=比计划靠下）与合格判定、**漏钉**清单、**多余钉痕**清单，以及合格/不合格
总判定。「清空检测」清空全部录入并返回录入态。

### 领域模型：有序对齐的全局动态规划（非最近邻）

配对是序列对齐问题（`src/lib/stapleInspection.ts` 的 `alignStaples()`）。
两条序列都自上而下排列，在 `(m+1)×(n+1)` 的 DP 网格上，每格有三种转移：

- **配对**（对角线）：计划位 i 配实测痕 j，代价 `|planned[i] − measured[j]|`；
- **漏钉**（上方）：漏掉计划位 i，**罚两倍容差**（`2 × tolerance`）；
- **多余**（左方）：实测痕 j 无计划位对应，同样**罚两倍容差**。

**不能用逐点最近邻代替**：最近邻只看局部距离，会让一个计划位抢走本应配给
前一个计划位的钉痕（如计划 0/10、实测 11：贪心 0→11 代价 11，全局最优是
漏掉 0、10→11 代价 1）。单测用多个此类贪心会错配的样本，配合穷举全部保序
匹配的参照实现，验证 DP 取到全局最小总代价。

**稳定决胜**（总代价相同时，依次比较）：

1. **未配对项更少**（漏钉 + 多余钉痕总数小）的路径优先；
2. 仍相同则**较早实测痕**优先：逐对比较配对所用实测痕的自上而下序号，
   首个较小者优先；
3. 仍相同则比较配对计划位序号（确定性兜底）。

### 待修正态与撤销

「分析钉位」先做纯函数校验（`validateStapleInput()`），任一问题都**停留在
待修正态**、不产生诊断，并定位到对应字段/列表项：

- 书脊长度、允许偏差为空、非十进制数字或非正数；
- 列表未**严格递增**（倒挂）、**项目重复**、某项**超出书脊**（< 0 或
  > 书脊长度）、或整列未填写（参数不完整）。

界面把出错字段标红、出错列表项加红圈，并把焦点移到第一个问题字段。

**分析后改动任一输入（四个字段中的任意一个）立即撤销旧诊断**，回到录入态
（录入内容保留）；必须重新点击「分析钉位」才会产生新诊断。

- **隔离**：钉位检测不读取、不改写拼版核版与走纸演练；做检测、清空检测
  都不会改变已有总页数、纸张展示面或演练轨迹；反过来修改拼版输入、操作
  演练也不撤销或改写当前钉位诊断。

## 翻面语义

每张纸有“正面 / 背面”切换按钮。翻面**只改变当前这一张展示的面**：

- 页码取自同一份预先生成、不可变的拼版结果（`spreadOf(sheet, side)`），
  **不重新计算、不重新排列**；
- 不影响其他纸张，也不改变外层→内层的折手顺序和纸张总数；
- 总页数输入一旦变化（包括变非法后再改回），各张的展示面统一重置为正面。

```bash
npm install
npm run dev        # 开发服务器
npm run build      # tsc 类型检查 + Vite 构建到 dist/
```

## 测试

```bash
npm test           # Vitest：公式边界、校验、清版与翻面只读语义
npm run test:e2e   # Playwright：自动起 vite preview 后走通输入/翻面/错误清理
npm run verify     # 构建 + 单测 + e2e 全量验收
```

- Vitest 覆盖：N=4 与 N=64 公式边界、最内层中缝连续页、每张四页恰好
  覆盖 1..N 不重复、折手单调序、空/小数/越界/不整除四类拒绝原因；
  演练模型的八姿态闭包、逆变换（rotate⁴ = flip² = id）、
  旋转/翻纸不可交换顺序、轨迹污染拒绝与 24 步上限；
  钉位检测的解析与四类列表拒绝原因、DP 对穷举参照的全局最优性
  （含多个逐点最近邻错配样本）、两倍容差罚分、等代价下未配对更少与
  较早实测痕的稳定决胜、超过安全整数范围的精确十进制语义（超大书脊
  原值保留、严格递增大整数不误判重复、超大容差下末端吻合的低成本匹配）。
- Playwright 覆盖：首屏空态、合法输入的逐张页序与纸张数、翻面仅改当前面、
  非法输入与清空输入时旧拼版被立即移除；演练区两种动作的实时画面、
  回起点性质、不可交换布局、24 步上限反馈，以及与既有核版交互的
  状态隔离；钉位检测的混合漏钉与多余钉痕全流程（连线、偏差、清单、
  判定）、超差标红、待修正态定位、分析后编辑即撤销、清空检测，以及
  检测前后拼版与走纸演练内容保持不变。

## Docker Compose

只运行静态 Web（nginx 托管 `dist/`）。容器内监听 8080，
**宿主机端口可用 `WEB_PORT` 覆盖**，默认 8080：

```bash
docker compose up --build            # http://localhost:8080
WEB_PORT=9000 docker compose up -d   # http://localhost:9000
```

一次性验收服务 `verify`（**自动构建镜像** → 类型检查/构建 → Vitest → Playwright
走通输入、翻面与错误清理的页面检查，全部通过即退出，不常驻）：

```bash
npm run verify:docker
# 等价于：docker compose --profile verify run --rm --build verify
```

> `--build` 强制每次重新构建镜像，避免误用旧的失败镜像层。镜像内浏览器版本与
> `package-lock.json` 中的 `@playwright/test` 版本严格对应；升级 Playwright 后
> 需同步修改 `Dockerfile` 中验收阶段的镜像标签（官方镜像仅提供
> jammy/noble 变体，无 bookworm 标签）。
